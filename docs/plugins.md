# Plugins

Plugins are optional and disabled by default. Open Settings > Plugins, then use the centered three-dot menu to enable or disable the bundled employer facts plugin. The arrow opens its separate settings page; its only control is Debug output, which reads that plugin's own errors. You can also set `plugins.sponsorship.enabled: true` in your configuration. Saving changes does not start a fetch or analysis; enabled hooks run during the next corresponding command. Disabling hides the display immediately. Existing results are retained. Analysis results do not change eligibility, scores, filtering or ordering.

The host discovers `plugins/<id>/manifest.json` without importing plugin code. A manifest declares its ID, version, host API compatibility, entry point, hooks, network use, display support and languages. The current API version is 1. Plugin code runs in a child process. Installed plugin code is trusted; the process boundary contains ordinary crashes and hangs and is not a sandbox for hostile code.

The fetch hook may refresh reference data. The analyze hook receives a JSON request with API version, hook, plugin configuration and data directory, and a list of `{uid, company, title, source, listing_date, first_seen_at, last_seen_at, dedupe_group}` records. It runs after the analysis transaction commits and returns a JSON result with `analysis_id` and a `results` map keyed by UID. Each UID maps `zh` and `en` to precomputed `badges` and `sections`. Only validated results for the current successful analysis are shown. The built-in plugin performs no network access during analysis.

Each database has a private adjacent `.<database-name>.plugins/` directory. Each plugin has `data/`, bounded `debug.json`, and `results.json`. Disabling or uninstalling a plugin leaves those files in place so they can be copied or exported. Invalid, incomplete or old results are hidden from the panel. The bounded debug log records the time, stage, failure type and plugin file/line when available. It excludes raw exception messages, configuration, job inputs and arbitrary stdout. Read failures degrade to an empty output; write failures never fail the core command. The log is private to each database and plugin.

The host limits manifest, request, result and diagnostic sizes and applies a wall-clock timeout. On POSIX it terminates the process group, and on Windows it uses the existing Job Object process-tree adapter. CPU and output-file limits apply on POSIX; Linux has a 512 MiB address-space limit. macOS observes process-group RSS and kills the group above a 512 MiB budget. Windows applies a 512 MiB Job Object memory limit. Native Windows behavior requires platform acceptance checks. The offline hook also denies Python network events and external process launches before plugin import; native hostile code is outside this trusted-plugin contract.

The host validates bounded JSON and never imports plugin code in a web request. Invalid manifests, missing modules, bad configuration, exceptions, nonzero exits, timeouts, malformed results and unavailable storage disable the affected operation and are isolated from panel, fetch and core analysis. Parent pipeline timeouts and user interruptions still propagate normally.

API 1 is experimental. The bundled manifest declares compatibility with host API 1, not every future core version. Install or upgrade trusted code explicitly. The first release has no marketplace, arbitrary CSS/HTML injection, sort/filter hooks or core-database write permission.
