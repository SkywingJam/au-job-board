# Map plugin frontend

The iframe displays the core's frozen summary snapshot. Counts use the snapshot's `count_unit`; selected postcode lists keep `core_order`. Only postcode facts and uniquely resolved locality facts with one postcode and a locally available polygon are placed. Other locations appear in the separately scoped list. A marker is the reference area's representative point, not an employer location. The summary counts jobs whose marker is in the current view (live while moving) and opens them as a list; this affects only the map display. Outlines load on demand when a postcode is opened. A compass restores north. Long result lists render 60 cards at a time and add more as they are scrolled. Jobs that only name one of the eight capitals appear as a dashed citywide pill near that city's CBD postcode point (from the bundled index), only while that point is in view, placed on the nearest spot clear of postcode circles and other pills, with a dashed leader when moved away; when the view covers at least 70% of Australia, postcode circles and capital pills are hidden and a single all-of-Australia pill lists every job in the current results; they are not assigned to any postcode and not counted in view. Other locations lists the rest; state-only groups appear only for states in view (rough state extents), largest group first, and the button count matches the list. Trackpad scrolling over count markers passes through to the map. Switching back to the list uses the host toolbar; opening a job uses the host bridge.

The map uses the locally bundled MapLibre GL JS 6.17.0 distribution from the official npm package `maplibre-gl@6.17.0`, released at https://github.com/maplibre/maplibre-gl-js/releases/tag/v6.17.0. The npm tarball SHA-256 is `587807d8d6c99349022e027fa310c16cfaa55392131f6263df080306db6809b0`. The package's BSD license is in `web/vendor/LICENSE.txt`. The style URL is `https://tiles.openfreemap.org/styles/positron` for the light theme and `https://tiles.openfreemap.org/styles/dark` for the dark theme, tinted at load (blue water, green parks and woodland; the dark style gets an added park layer from the same tiles). Only a failure before the style loads switches to the local fallback; later single tile errors keep the basemap. Map resource URLs outside `https://tiles.openfreemap.org` are rejected. The frame requests an origin-only Referer. The host must also enforce the declared network policy and Referrer-Policy; CSP and frame headers are outside this directory's ownership.

The default opaque `sandbox="allow-scripts"` requires cross-origin permission for ES modules and module workers served by the host. Without it the local MapLibre module or worker can be blocked. The frontend falls back to local SVG geometry, postcode markers and job lists when the module cannot load. In the synthetic Chromium/Brave harness with an opaque frame and no asset CORS header, the module request fails with `origin null ... blocked by CORS policy: No Access-Control-Allow-Origin header`. With `Access-Control-Allow-Origin: *` on synthetic assets and the basemap deliberately blocked, the local fallback remains usable. The synthetic run does not establish worker startup; the real host (CSP `worker-src` allowing the data-URL module worker) was verified in a browser with the basemap and worker running. Keep testing module and worker loading under the actual sandbox and CSP after changes; do not add `allow-same-origin` as a workaround without a separate review. A basemap resource error is reported while local geometry and lists remain available. The SVG fallback supports pan, zoom and the in-view list without network access.

Synthetic browser regression: `node tools/test_map_frontend.mjs`. It requires Playwright and a local Chromium-compatible browser; `PLAYWRIGHT_MODULE` and `CHROMIUM_PATH` can select existing installations. The script serves only synthetic data on an ephemeral loopback port.
